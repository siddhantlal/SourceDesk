# Scope and limitations

- **Text PDFs only.** OCR, reliable table/layout understanding, scanned pages, images and guaranteed multilingual extraction are not implemented. Insufficient text is an explicit processing failure. Content filters are restricted to unfiltered, Flate, ASCII85 and ASCII85-to-Flate text streams; other filters/predictors fail closed. Decoded-byte, stream-count and Form-depth/invocation bounds reduce expansion risk, not provide a complete PDF sandbox.
- **Browser workspace plus API.** A responsive same-origin frontend is available at `/`; Swagger remains at `/docs`. Browser checks used local Chrome at desktop and mobile widths, not every browser or a formal accessibility audit.
- **Default fake providers.** Signed hashing and deterministic sentence extraction exercise dataflow and isolation, not semantic embeddings or genuine model quality. A fake may select a sentence with overlapping words even when it does not answer the question. Its output always needs the fake label.
- **External provider unverified without credentials.** An OpenAI-compatible HTTP adapter and opt-in smoke command exist, but fake runs do not establish API/model availability, semantic accuracy, latency or spend for real models. Cost is unavailable without verified dated pricing, never assumed zero.
- **Small draft evaluation.** Three original fictional PDFs and twelve draft questions are a reproducible fixture, not the original target of ten PDFs/fifty human-reviewed questions. No human semantic correctness, citation-support or unsupported-claim score is claimed.
- **Exact search baseline.** No approximate index, hybrid keyword retrieval, reranker or calibrated similarity threshold. Cosine distance is not answer confidence. Small-corpus measurements do not predict production scale.
- **Fixed index dimensions.** Schema v1 uses 1536-dimensional vectors. Changing dimensions requires a migration and reindex. Provider/model/chunk changes require a rebuild; different models are never silently mixed in retrieval.
- **Small durable worker.** One document at a time per worker; PostgreSQL leases and fencing protect publication. Retries may repeat paid external work. A long blocked parser/provider operation can exceed a lease. There is no distributed scheduler, global concurrency quota or exactly-once billing guarantee.
- **Local storage.** Storage is abstracted but only local disk is implemented. All API/worker instances need the same configured directory. A durable deletion outbox retries committed file-removal work, but object storage, atomic DB/filesystem transactions and automatic reconciliation of files orphaned during upload are not implemented.
- **No production security claim.** No email verification/reset, token revocation list, centralized rate limiter, PDF sandbox, per-user disk quota, TLS termination or managed secret rotation. Bind to localhost for the demo. See security.md before exposing it.
- **Historical deletion policy.** Deleting a document removes its index/original, not the answer text or all persisted evidence snapshots. Public deleted-source excerpts are redacted. Full account/legal erasure and backup/provider deletion need separate design.
- **Compact tests.** The initial suite samples the main risks rather than imposing a coverage percentage or exhaustively automating every adversarial edge case. Check the actual execution report for function/case counts, skips and failures. Do not treat a limited suite as exhaustive assurance.
- **Container-free setup.** Native PostgreSQL/pgvector must be installed. On the verified Windows host the database runs in Ubuntu WSL and Python runs natively; WSL/service lifetime and refreshing the private TCP address matter. CI is provided as a workflow, not claimed executed on GitHub without a remote run.

## Sensible next work

Human-review and expand the evaluation corpus before tuning retrieval. Verify real providers explicitly, then audit claim-level support and measure model-specific usage. Add bounded parser isolation and practical login/upload abuse controls before multi-user exposure. Only introduce approximate indexing or reranking after measuring the exact-search baseline and preserving tenant filters. Add file reconciliation and a complete retention/erasure policy before relying on stored research data.
